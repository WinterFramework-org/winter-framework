# 검증 방법

### 검증 범위 선택

- 변경한 동작과 영향 범위에 맞춰 단위·통합·E2E 검증을 선택한다.
- 개별 기능과 모듈 내부 동작은 해당 프로젝트(`winter-framework`, `mybatis-winter`)의 테스트를 우선한다.
- 프로젝트 간 조립, 실제 애플리케이션 기동과 전체 요청 흐름을 확인할 필요가 있을 때 별도 `winter-samples` 프로젝트에서 검증한다.
- 모든 변경에 E2E 검증을 일괄 적용하지 않는다.

### 검증 대상과 재현 코드 준비

- `winter-samples`를 사용하는 경우, 검증할 동작에 필요한 재현 코드를 준비하고 수정한 Winter 코드가 실행되도록 의존성을 연결한다.
- 의존성의 버전 번호 일치만으로 수정본 사용을 단정하지 않는다. 참조 대상이 불명확하면 클래스나 JAR의 실제 로딩 위치를 확인한다.

### 검증용 샘플 변경과 정리

- 재현과 검증에 필요한 샘플 코드·설정은 분리된 검증용 작업 공간에서 변경하며, 원본 샘플은 보존한다. 지정된 공간이 없으면 사용할 공간을 먼저 확인한다.
- 검증이 끝나면 임시 변경을 되돌릴지 사용자에게 확인한다. 확인 후 이번 검증용 변경만 되돌리고, 기존 사용자 변경과 개인 환경 설정은 보존한다.
- 프레임워크 검증 목적으로 샘플에 가한 변경은 커밋에 포함하지 않는다. 샘플 자체의 기능·테스트 반영을 별도로 요청받은 경우에는 해당 요청 범위를 따른다.
- 개인 환경 설정과 비밀정보는 커밋에 포함하지 않는다.

### 검증 사례와 실행 안내

- 변경 시나리오와 직접 관련된 정상·경계·실패 사례를 필요한 범위에서 선택한다.
- 재현과 확인에 필요한 환경과 사전 조건, 실행 진입점, 입력, 확인 지점과 기대 결과를 안내한다.
